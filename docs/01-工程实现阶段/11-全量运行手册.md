# 11 全量运行手册（P3）

目标长篇（如斗破苍穹 1637 章）全量建库的操作手册。逐阶段闸门运行：
**Map 未验收不得继续 canonical/link/reduce**（11 §P3）。

## 0. 前置检查

```bash
# 数据库与迁移
novelcanon --version
# 配置（.env）：
#   LLM_MODEL / LLM_BASE_URL / LLM_API_KEY（不落库）——Map 抽取与正式压缩评测（llm-map）用
#   EMBEDDING_PROFILE_ID / EMBEDDING_BASE_URL / EMBEDDING_DIMENSION（+可选 MODEL/API_KEY）
#     ——生产 embedding 后端（API 按 active index profile 创建，密钥不落库）
# 质量门禁：pytest / ruff / mypy 全绿
```

## 1. 容量与 Token 预测

- 每章约 2000–4000 字 ≈ 1500–3000 token（按 profile.tokenizer 计量）；
- 1637 章 Map：input ≈ 1637 × 2500 ≈ 4.1M token；输出 ≈ 1637 × 800 ≈ 1.3M token；
- 加上 align/verify/link/reduce 阶段，总预算按 **8–12M token** 预估；
- 日预算：限流配置（requests_per_minute / tokens_per_minute）按 provider
  配额设置，避免触顶 429 重试风暴。

## 2. 备份（全量前必做）

```bash
# 数据库在线备份（WAL 安全，sqlite3 backup API）
novelcanon backup data/backups/novelcanon-pre-full.db

# 原始输入备份（EPUB/TXT 归档）
cp -r data/books data/backups/books-$(date +%F)

# 恢复演练（模拟灾难）：
rm data/novelcanon.db
novelcanon restore data/backups/novelcanon-pre-full.db data/novelcanon.db
# 输出：FK 违规=0 证据复现=N/N claims 重复=0 完整性=通过
```

完整性校验（任意时刻可跑）：`python -c "from novelcanon.ops import scan_integrity; ..."`。

## 3. 逐阶段闸门

```bash
# 阶段 06：逐章 Map（run 保持 running；checkpoint 可恢复）
novelcanon extract <book_id> --concurrency 4

# 检查 checkpoint 恢复：中断后重跑同一命令，已完成章节复用（reused 计数）
# 阶段 07：证据对齐
novelcanon align <book_id>
# 阶段 08：实体消歧
novelcanon resolve <book_id>
# 阶段 09：事件链接
novelcanon link <book_id>
# 激活（结构化查询可见；v_active_claims 只读 active run）
novelcanon activate <book_id>

# 阶段 10：索引 + 卷分组 + 分层摘要 + 查询验收
novelcanon index <book_id>
novelcanon group-volumes <book_id>
novelcanon summarize <book_id> [--deterministic | LLM 模式]
novelcanon query "萧炎现在的修为" --book-id <book_id>

# 阶段 11：评测与完整性
novelcanon pilot <book_id> --golden golden.json  # 正式评测：冻结黄金集文件（校验 book/章节/hash）
# 正式压缩评测：自动注入生产 LLM Map 抽取器（llm-map，需 LLM 配置；未配置报错退出）
novelcanon pilot <book_id> --golden golden.json --compressed --out pilot.json
novelcanon pilot <book_id> --golden golden.json --compressed --extraction-mode golden-replay  # 仅 oracle 辅助验证（决策门拒绝启用压缩）
novelcanon pilot <book_id>            # 仅黄金样例验收：4 章 fixture 黄金集（提示使用 --golden）
novelcanon scan-leakage <book_id>     # cutoff 泄露扫描（必须为零）
```

**P1/P2 正式报告前置**（fixture 之外的正式阈值验收）：

- 为目标长篇**人工冻结**评测黄金集：QA（期望引用章节）、实体合并对、
  事实（claim_type + 描述 + 章节 + 直接证据 span）、结构化 claims、
  因果边、书内容 hash；以 JSON 文件（schema `golden-v1`）保存，
  `novelcanon pilot <book_id> --golden golden.json --out pilot.json
  --compressed` 生成报告（加载时校验 book_id / 章节范围 / 内容 hash，
  错配直接拒绝；书内容 hash 缺失直接拒绝）；
- **压缩重抽取必须走真实 LLM Map 抽取器**（复审 P0）：正式命令
  （`--golden --compressed`）自动构造生产 Map 抽取器（llm-map，复用
  阶段 06 Map 流水线 + `NOVELCANON_LLM_*` 配置）；未配置 LLM 时报错
  退出，**不会静默回退 golden-replay**（golden-replay 只允许显式
  `--extraction-mode golden-replay` 用于 fixture oracle 辅助验证，且
  决策门 extraction_mode 硬前置拒绝其授权启用压缩）；
- 报告须含：核心/全部实体合并 F1、事实 precision/recall、证据 hash
  复现率（阈值 100%，**分母为完整冻结黄金证据集 golden.evidence_spans，
  与基线路线一致**，不得改用 claims 的 span 缩小分母）、QA 章节正确率、
  因果边 precision、**每万字 Token/时间/成本**（usage 报告 + 全链路
  stage 账本：rewrite / map / 消歧 / 证据验证 / 链接 / reduce；
  **每万字分母 = 原始语料字数**，阶段行保留各自输入量，不得重复累计）；
- 压缩决策门（gate-v2）：后验全部通过 + **生产抽取模式（llm-map /
  production-map）为硬前置**，recall 差 ≤0.02 / 证据复现不退化 / QA
  不退化 / 成本节省 ≥10% 四条件；
- 生产 embedding 后端（复审 P1）：API 按 active index 的
  `embedding_profile_id` 经 `retrieval.factory` 创建后端——配置
  `NOVELCANON_EMBEDDING_PROFILE_ID` + `_BASE_URL` + `_DIMENSION`
  （+ 可选 `_MODEL` / `_API_KEY`，密钥不落库）后启动自动注册 OpenAI
  兼容 `OpenAICompatEmbedder`；未注册 profile 返回稳定 500
  `backend_not_configured`（服务端配置错误）；
- P1（30 万字短篇）与 P2（200–300 章主样本）阈值按《定版方案》§14.2，
  在查看正式评测结果前写入测试配置（冻结，防假通过）。

**闸门规则**：每阶段先小窗口抽查（如 limit 3 章）验收，再全量推进；Map
未验收不进入 canonical/link/reduce。

## 4. 监控

- 磁盘/WAL：SQLite WAL 模式下手动 checkpoint（`PRAGMA wal_checkpoint(TRUNCATE)`）
  或定期 `novelcanon backup`（backup 前自动 checkpoint）；
- Token 账本：`token_ledger` 表（stage=map/align/link/summary/query）——
  `SELECT stage, SUM(input_tokens+output_tokens) FROM token_ledger GROUP BY stage`；
- 失败章节：`run_checkpoints.status='failed'` + `evidence_errors` 表。

## 5. 失败处理

- 单章失败：修正后 `novelcanon extract` 重跑（checkpoint 幂等复用）；
- 批量失败（限流/网络）：提高重试、降低 concurrency，账本自动记录 retry；
- 阶段验证失败：`novelcanon activate` 前 run 保持在 ready_to_activate，
  修复数据后重新验证；
- 人工处理流程：evidence_errors 按 error_code 分类，P0 错误（schema/ID）
  修复数据契约后重跑对应阶段。

## 6. 索引重建演练

```bash
# 配置（chunking/tokenizer）变化 → 新 chunking_version → 全量重建
novelcanon index <book_id>            # 旧 active → retired，新 → active（原子）
# 单章内容修订 → 只重建该章（同一 active 版本内原子替换）
# 重建后 query 缓存自动失效（active index version 入缓存键）
```

## 7. 最终验收（11 退出标准）

- 目标长篇完成单一 active 全量 run；
- 所有正式回答可追溯到 supported evidence（QA sources 带章节/span）；
- 备份、恢复、索引重建、失败重跑均演练通过；
- 质量/成本/吞吐/错误率有持续可观察基线（Pilot 报告 + stats）；
- 后续变更遵循「先契约、再 migration、再代码、最后重建/回归」。
