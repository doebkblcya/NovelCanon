# 02 数据契约与存储

## 目标

把《定版方案》中的事实、证据、版本和运行语义落实为可迁移、可约束、可测试的 SQLite 数据契约。

## 前置条件

- 阶段 01 工程骨架完成。
- 已确定 Schema 表达和 migration 工具。
- 已整理定版方案中的所有核心表和索引。

## 实施顺序

### 1. 定义领域 Schema

优先定义：

- ExtractionDraftV1；
- CanonicalMemoryV4；
- entity、mention、alias claim；
- 公共 claim envelope；
- relation、event、state、org、foreshadowing；
- claim evidence；
- event link；
- generation/embedding profile；
- query result 与 evidence citation。

标准字段必须引用统一 ontology 和 state catalog。模型原始自由文本只能进入明确允许的 raw 字段。

### 2. 实现稳定 ID

集中实现 ID 生成，不允许各模块自行拼接：

- chapter_id：导入时生成并持久化；
- raw_chunk_id：稳定章节、切分版本和锚点；
- canonical_id：独立于名称和章节顺序；
- fact_id：表示可连续修订的事实槽；
- claim_version_id：fact_id、payload hash 和 schema version；
- evidence_id：基于 claim version 和稳定 source span。

为每种 claim 类型编写“哪些字段进入 fact_id”的明确测试。

### 3. 创建 DDL 和 migration

落实定版方案 §8 的核心表、外键、唯一约束和检查约束。类型专属 payload 使用一对一子表，不放入单个大型 JSON 字段。

必须覆盖的索引：

- observed_ordinal；
- claim_version_id、supersedes_version_id；
- event_links 的 source/target event；
- event_participants 的 entity/event；
- entity_mentions.surface_name；
- book_id 与主要过滤字段构成的复合索引。

### 4. 实现 append-only 版本写入

- claims 历史版本不得更新或删除。
- update/retract 必须指向旧版本。
- 相同 payload 跨 run 复用同一 claim version。
- claim_observations 记录某次 run 对已有版本的观察。
- 任何“当前版本”都由查询视图推导，不额外复制一份可漂移状态。

### 5. 实现 staging 与 active 视图

- run 的中间结果写入 staging。
- 只有完成 canonical、evidence、index 验证的 run 才可激活。
- 默认 repository 只读取 active 且满足状态过滤的数据。
- 失败 run 可审计、可重试，但不得进入默认查询。

### 6. 建立黄金 fixture

至少覆盖：

- 同一事实重复观察；
- 状态值更新；
- 事实撤回；
- supports 与 refutes 形成 contested；
- 实体合并和拆分审计；
- 同名实体不应误合并；
- 两本书使用相同人物名但查询完全隔离。

## 产物

- 领域 Schema；
- ontology 和 state catalog 初始版本；
- SQLite 初始 migration；
- 稳定 ID 库；
- repository 和事务边界；
- 数据契约测试集。

## 验证

- 从空库迁移到最新版本成功。
- migration 可在数据库备份副本上升级。
- 相同输入重复运行不增加 fact/version/evidence。
- payload 改变时复用 fact_id 并新增 version。
- 跨 run 相同 payload 只新增 observation。
- foreign key check 无错误。
- explain query plan 能命中预期索引。

## 退出标准

- JSON/类型 Schema 与 DDL 能表达定版方案全部首期事实类型。
- 幂等、版本链、审计和多书隔离测试全部通过。
- active 查询无法读取失败或未激活 run。
- 数据契约变更已经具备 migration 和 schema version 规则。

## 风险控制

- 不用名称或 ordinal 生成实体稳定 ID。
- 不把 extraction run 写入 claim_version_id。
- 不在 entity 表复制 aliases。
- 不在 event 中复制 participants 或 causes。
- 不允许应用代码绕开 repository 直接修改历史 claim。
