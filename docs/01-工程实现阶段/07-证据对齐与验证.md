# 07 证据对齐与验证

## 目标

将 Draft 中的引用稳定映射回规范化原文，生成可复现 evidence，并根据证据立场决定 claim 是否能进入默认查询。

## 前置条件

- 原文 span 和 hash 往返测试为 100%。
- Map Draft 的 ref_source_segment 已通过范围校验。
- claim version 已能在 staging 中稳定生成。

## 证据处理链

~~~text
ref_source_segment
  -> 原文候选范围
  -> 字面匹配和 span 候选
  -> 语义/蕴含验证
  -> claim_evidence
  -> claim_status 聚合
~~~

## 实施顺序

### 1. 引用回映射

无压缩时，ref 直接映射到原文章节和半开区间。

有压缩时采用两级映射：

1. 压缩段 ID、段内 offset、段 hash；
2. compression segment 的 ref_seg；
3. 原文章节、原文 offset、原文 hash。

任一级 hash 或范围失败都必须进入 staging/error，不能猜测修复后直接激活。

### 2. span 候选生成

- 在引用范围内优先精确匹配。
- 允许规范化后的标点/空白容差，但最终 span 必须切自规范化原文。
- 多候选时按距离、literal match rate 和上下文排序。
- 保存候选选择过程的验证方法和版本。

### 3. 证据分类

对 evidence 设置两个独立维度：

- stance：supports、refutes、unclear；
- type：direct、contextual、inferred。

direct evidence 必须可以完整 hash 复现。inferred 不应伪装为 direct。

### 4. claim 状态聚合

严格执行：

| Evidence 组合 | Claim 状态 |
|---|---|
| 仅 unclear | unverified |
| 仅 supports | supported |
| supports 与 refutes 同时存在 | contested |
| 仅 refutes | rejected |

默认查询仅使用 supported。其他状态只有在诊断或显式请求时返回。

### 5. 多段和跨章证据

- 一个 claim 可以关联多段 evidence。
- primary_evidence_id 只用于查询加速。
- 跨章因果默认保留原因端和结果端证据。
- event link 的 observed ordinal 取全部支持证据的最大值。

### 6. 验证调用治理

- 先使用确定性字面规则，低置信情况才调用模型。
- 验证模型使用独立 prompt/profile/version。
- 验证调用单独计量，不并入 Map 调用。
- 同一 claim/span/version 的验证结果应可缓存复用。

## 产物

- ref 回映射器；
- span candidate generator；
- literal verifier；
- 可选 entailment verifier；
- status aggregator；
- evidence repository 和错误表；
- 证据黄金测试集。

## 验证

- direct span hash 复现率 100%。
- 越界、hash 不匹配和找不到原文的 claim 不会激活。
- 四种 claim status 聚合组合全部有测试。
- primary evidence 始终属于对应 claim version。
- 跨章证据的 max observed ordinal 正确。
- 重跑验证不会产生重复 evidence。

## 退出标准

- 每条 active claim 至少有符合策略的支持证据。
- 默认查询无法读到 unverified、contested 或 rejected。
- 证据错误可以追溯到 ref、候选选择和验证方法。
- QA 层已经可以返回精确章节和原文 span，而不是模型生成的引用描述。
