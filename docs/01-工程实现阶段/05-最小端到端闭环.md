# 05 最小端到端闭环

## 目标

用 3–5 章人工黄金样例跑通第一条完整纵向链路，证明原文、事实、证据、版本、激活和知识截止查询能够协同工作。

## 为什么需要这一阶段

数据表、导入器和流水线分别通过测试，并不等于整个系统成立。最小闭环用于尽早暴露跨模块契约错误，同时避免真实模型的不确定性干扰定位。

## 范围

首条链只覆盖：

- entity 和 alias；
- event；
- state；
- 一种 relation；
- direct supports evidence；
- knowledge_cutoff_chapter；
- FTS 原文查询。

使用手工固定的 ExtractionDraftV1，不调用真实生成模型，不实现复杂消歧、向量检索、因果递归和摘要。

## 黄金样例设计

3–5 章文本至少包含：

- 人物先以别名出现，后披露正式名；
- 一个状态值发生改变；
- 一段明确的一跳关系；
- 一个事件及参与者；
- 一条事实在后续章节被更新；
- 两个相似名称但不同的实体；
- 能精确定位的直接证据；
- 截止早期章节时必须隐藏的信息。

同时提交人工期望文件，包含实体、事实版本、证据 span、查询结果和截止章节结果。

## 实施步骤

1. 导入并规范化黄金原文。
2. 切章、chunk 并建立 FTS。
3. 由 fixture provider 返回固定 Draft。
4. 将 mention 映射到预设 canonical entity。
5. 生成稳定 fact/version ID。
6. 对齐原文证据并验证 hash。
7. 聚合为 supported claim。
8. 完成 run 验证和原子激活。
9. 执行结构化查询和 FTS 查询。
10. 重复整条流水线验证幂等。

## 必测查询

- 指定人物当前状态及证据；
- 某章截止前人物展示名称；
- 一跳关系及证据；
- 某事件参与者；
- 原句/关键词 FTS；
- 更新前后的 claim 版本历史；
- knowledge_cutoff_chapter 前后的结果差异；
- 指定错误 book_id 时返回空结果。

## 产物

- 小型中文黄金小说；
- 固定 Draft；
- 人工 canonical 映射；
- 期望数据库快照或期望查询结果；
- 端到端测试命令；
- 首份 run/Token/错误报告。

## 验证

- 所有 direct evidence span hash 复现率 100%。
- 同一输入运行两次，fact/version/evidence 数量不增加。
- 状态更新复用 fact_id 并新增 claim version。
- cutoff 前看不到后期 alias、claim 或相关证据。
- 所有回答均包含 chapter_id、ordinal 和 source span。
- 失败 run 不改变此前的查询结果。

## 退出标准

- 一条命令可以从空库生成可查询的 active 数据。
- 端到端测试在无网络环境稳定通过。
- 数据库中的每条 active claim 都能回到原文证据。
- 项目具备后续接入真实抽取模型的可靠基线。

## 不应提前加入

- Prompt 调优；
- 自动实体合并；
- 复杂事件因果；
- 压缩；
- 卷/全书摘要；
- Web API。
