# NovelCanon 定版方案

## 1. 目标与边界

NovelCanon 将中文长篇完结小说转换为可追溯、可按章节查询的结构化知识库。目标语料规模为 400–700 万字、约 2000 章。

必须支持：

- 人物、地点、物品和势力的统一实体标识；
- 关系、状态、势力成员和事件的跨章变化；
- 事件因果链；
- 原文全文检索、语义检索和结构化查询；
- 带原文证据的问答；
- 章节、卷和全书摘要；
- `knowledge_cutoff_chapter=N` 信息截止查询；API 可保留 `as_of_chapter` 兼容别名。

首期不实现：

- 图数据库和图算法；
- 开放式多跳关系推理；
- 分层图的逐层模型选择；
- Agent 工具循环；
- 伏笔状态机；
- 分角色可见性权限；
- 增量追更和创作辅助。

SQLite 是唯一权威数据源。未来需要图算法时，从 SQLite 生成可重建的图投影，不建立第二事实源。

核心目标：在可控 Token 预算（见 §12）内完成全书建库与查询；外部处理组件通过版本化运行配置替换（见 §13）。

数据范围：单库可容纳多本书，`book_id` 贯穿全部表（chapters/raw_chunks/claims/event_links 等）隔离数据；§12 预算按单书 700 万字口径，多书按需线性叠加。

## 2. 系统架构

```text
原文 TXT/EPUB
  → 文本规范化与章节切分
  → 原文 raw chunk、FTS 索引和向量索引
  → 原文规则预扫描
  → 可选受约束压缩
  → 逐章 Map 抽取 ExtractionDraftV1
  → 全书实体消歧
  → EventLinker 事件链接
  → 原文证据对齐与验证
  → CanonicalMemoryV4
  → SQLite 单库
  → 分层 Reduce
  → 结构化查询、混合检索、因果查询和问答
```

处理层与存储层分离：抽取、消歧、链接和验证均在落入正式事实表前完成；SQLite 负责持久化、索引、事务和查询。

## 3. 文本与章节

### 3.1 文本规范化

入库前统一执行：

- UTF-8 解码；
- Unicode NFC 规范化；
- 换行统一为 `LF`；
- 保留规范化前后的内容哈希；
- 所有字符偏移使用 Unicode code point；
- 所有区间使用半开区间 `[start, end)`。

原始文件只读保存。后续抽取、证据偏移和检索均基于规范化文本。

### 3.2 章节标识

章节使用稳定 `chapter_id` 和可排序 `ordinal`：

```text
chapter_id     导入时分配并持久化的稳定 UUID；已有来源 ID 时保留映射
ordinal        当前版本中的章节顺序
title          章节标题
char_start/end 章节在规范化全书文本中的范围
content_hash   章节内容哈希
volume_id      所属卷（见 §10 卷分组规则）
```

`ordinal` 不参与稳定 ID 生成。插章或重排只更新 ordinal。

### 3.3 Raw chunk

原文检索块按 embedding tokenizer 切分，不按字符数切分：

```text
raw_chunk_id          hash(chapter_id + chunking_version + anchor_hash)
source_chapter_id     稳定章节 ID
chunking_version      切分策略版本
token_start/end       tokenizer token 区间
char_start/end        章内 Unicode code point 区间
token_count           实际 token 数
content_hash          chunk 内容哈希
embedding_profile     向量配置标识
embedding_dimension   运行时从模型配置读取并校验
observed_ordinal      所属章节 ordinal
```

默认块长 300–450 tokens，重叠 15%–20%。具体上限不得超过 embedding 输入窗口。切分策略或向量配置变化时创建新版本，完成新索引后再原子切换。章节内容修订（`content_hash` 变化）时，失效该章全部 raw chunk 与关联证据，重建后原子替换，不得保留新旧混合索引。向量索引（`embedding_records` 对应的向量虚表）随 raw chunk 版本重建，同一时刻仅激活一个索引版本；增量重建期间旧版本保持可查，切换为瞬时有界操作。

## 4. 抽取契约

### 4.1 ExtractionDraftV1

Map 按章并发执行，仅输出本章可确定的信息：

```text
mention_id              本章实体提及 ID
local_event_id          本章事件 ID
provisional_claim_id    临时事实 ID
ref_source_segment      压缩段到原文范围的映射
local_causes[]          仅引用同章 local_event_id
cause_candidates[]      跨章原因的文本描述和候选实体
claims[]                关系、事件、状态、势力和伏笔候选
unresolved[]            无法消歧的实体提及
```

Draft 不包含 `canonical_id`、最终证据坐标或跨章事件 ID，也不抽取未来结果。

`ref_source_segment` 使用稳定定位三元组：`压缩段 ID + 段内字符偏移 + 段内容 hash`；压缩段自身携带 `ref_seg`（原文章号 + 原文半开区间 + 原文 hash），Draft 经两级映射还原到规范化原文坐标。压缩关闭时，`ref_source_segment` 直接指向原文区间。

`unresolved[]` 落库保留并统计数量与占比，不参与默认查询；同一实体跨章多次 unresolved 时由 EntityResolver 第二遍按上下文复判，仍无法消歧的进入人工标注队列（P2 提供标注工具）。EventLinker 只消费已完成 canonical 映射的实体和事件，不承担实体消歧。

### 4.2 CanonicalMemoryV4

全书消歧、事件链接和证据验证完成后生成：

```text
entities[]
claims[]
claim_evidence[]
event_links[]
unresolved[]
```

实体最小字段：

```text
canonical_id       稳定标识，跨 run 不变
canonical_name     内部规范名，不直接用于 knowledge cutoff 查询展示
tier               核心/主要/次要/一次性（importance 分层，图谱渲染与查询排序用）
importance_score   0–100，抽取端按出场频率、共现度与叙述权重粗估，供降权
```

别名只存入 `entity_alias_claims`，实体表不保存 `aliases[]` 副本。按进度展示名称时，从 `observed_ordinal <= knowledge_cutoff_chapter` 的 alias claim 中选择，不使用全书最终名称。

世界内术语仅表示不参与关系、持有、地点或事件链接的纯概念。人物、势力、地点、物品、功法和宝物只要参与结构化关系，就必须建为 entity；其释义存入版本化 `term_definition_claims` 并可关联 `canonical_id`。每条释义记录 `first_observed_ordinal` 和证据，可更新或撤回。

每条事实使用公共 envelope：

```text
fact_id                 跨 extraction run 稳定的事实标识
claim_version_id        事实版本标识
claim_type              relation/event/state/org/foreshadowing/event_link/term_definition
operation               assert/update/retract
supersedes_version_id   update/retract 指向的旧版本
confidence              0–1
claim_status            unverified/supported/contested/rejected
observed_chapter_id     首次披露章节
observed_ordinal        首次披露章节序号
world_valid_kind        story_time/chapter_proxy/unknown
world_valid_from/to     世界有效区间；可空
world_valid_confidence  世界时间置信度
created_by_run_id        首次创建该版本的 run
prompt_version
pipeline_version
created_at
primary_evidence_id     可空，仅作查询加速
```

类型专属字段存入一对一子表，不将所有 payload 塞入单个 JSON 大字段。

### 4.3 稳定 ID 与版本

`fact_id` 表示可连续修订的事实槽，不包含会随版本变化的值。按 claim 类型分别生成：

- relation：主体、关系类型、客体和关系上下文；
- event：事件类型、参与者、地点、章节锚点和事件序号；
- state：主体、状态字段和目标，不包含 value；
- org：势力、成员和角色；动作与状态写入版本 payload；
- foreshadowing：线索锚点和关联实体。

`claim_version_id` 由 `fact_id + payload_hash + schema_version` 生成，不包含 extraction run。所有版本 append-only；新版本通过 `supersedes_version_id` 连接旧版本，不覆盖历史记录。`claim_observations(claim_version_id, extraction_run_id)` 记录某次 run 观察到的既有版本。重复运行产生相同 payload 时只新增 observation，不新增 claim version。

实体 `canonical_id` 独立于名称和章节顺序。实体合并、拆分和别名变化写入审计表。

### 4.4 时间语义

系统区分三种时间：

- `observed`：文本在哪一章披露；用于 `knowledge_cutoff_chapter`；
- `world_valid`：事实在故事世界中何时有效；无法可靠推断时为 unknown；
- `ingested_at`：系统处理时间。

首期允许以章节顺序近似世界时间，但必须标记 `world_valid_kind=chapter_proxy`，不得伪装为确定故事时间。

所有派生产物必须记录 `max_observed_ordinal`，包括实体别名、事件链接、卷摘要和全书摘要。

## 5. 事实类型

### 5.1 Relation

```text
from_entity_id
to_entity_id
relation_type
relation_raw
direction
```

关系类型来自受控本体；原文短语保存在 `relation_raw`。本体值域、事件类型与中文别名映射集中在单一 ontology 模块；新增类型须更新 ontology 与 schema 版本，禁止自由文本直接进入标准字段。

### 5.2 Event

```text
global_event_id
event_type
summary
location_entity_id
sequence_in_chapter
narrative_weight
```

参与者只存入 `event_participants` 关联表，Event 不保存 `participants[]` 副本。Event 也不内嵌 `causes[]` 或 `results[]`；因果关系只存于 event_links。

### 5.3 Event link

event_links 是一等事实表：

```text
fact_id / claim_version_id
source_event_id
target_event_id
relation_type       causes/enables/prevents
confidence
claim_status
observed_chapter_id / observed_ordinal
primary_evidence_id
```

`results` 是 `causes` 的反向查询结果，不单独存储。

### 5.4 State

状态字段由 state catalog 约束：

```text
field               value_type           multivalued  target_required
stance              relation_stance      false        true
cultivation_realm   ordered_enum         false        false
alive               bool                 false        false
identity            canonical_ref        false        false
location            canonical_ref        false        false
possession          canonical_ref        true         true
```

catalog 记录枚举、标准化器、单位、排序值和适用实体类型。自由文本只进入 raw value 和证据，不直接作为可查询标准值。扩展枚举须更新 catalog 版本号并执行迁移，不直接追加未定义值。

### 5.5 Organization

势力事件至少包含：

```text
org_entity_id
member_entity_id
role
action              join/leave/promote/demote/found/dissolve
```

成员列表和势力状态由事件日志按查询时间派生。

### 5.6 Foreshadowing

首期只记录线索候选、原因、关联实体和证据，不维护 open/progress/payoff 状态机。

## 6. 证据模型

source span 只存在于 `claim_evidence`：

```text
evidence_id
claim_version_id
evidence_stance       supports/refutes/unclear
evidence_type         direct/contextual/inferred
chapter_id
char_start/end
span_hash
literal_match_rate
verification_method
verification_run_id
```

claim 只允许保存 `primary_evidence_id` 指针，不复制 span。

证据处理流程：

```text
ref_source_segment
  → 回溯对应原文范围
  → 字面匹配与候选 span 生成
  → 蕴含验证
  → 写入 claim_evidence
  → 聚合 evidence_stance 得到 claim_status
```

直接证据的 span 必须能够在规范化原文上按 hash 完整复现。一个 claim 可以关联多段证据，跨章因果默认至少保留原因端和结果端证据。

验证失败处理：span 无法按 hash 复现时，claim 和失败原因保留在 staging/error 表，但不得进入激活事实视图。证据状态按以下规则聚合：仅 `unclear` → `unverified`；仅 `supports` → `supported`；同时存在 `supports` 与 `refutes` → `contested`；仅 `refutes` → `rejected`。除 `supported` 外，其余状态默认不进入回答。验证调用单独计量（属 §12 证据验证批次）。

## 7. 可选压缩

压缩是实验开关，不是数据正确性的前提。原文始终完整索引。

压缩比例统一使用“输出保留率”：玄幻/都市/系统流默认保留 50%–60%；历史/江湖保留 65%–75%；悬疑/权谋/伏笔密集题材保留 80%–90% 或禁压。题材和保留率为输入配置，随 `compression_version` 记录；§12 的 `r` 与此定义一致。

### 7.1 规则预扫描

压缩前以规则扫描全书重复短语、专名、数字、时间表达和高频意象，生成逐字保留词典。该阶段不调用生成模型。

### 7.2 受约束改写

每个输入段输出：

```text
keep       逐字保留
rewrite    精简但保留专名、数字、时间词和关键对话
drop       删除并记录 reason
ref_seg    指向稳定原文范围和 hash
```

### 7.3 后验校验

压缩后比较实体、数字、时间表达和豁免词覆盖率。低于阈值的段落自动回退原文。压缩是否默认开启由 Pilot 中相对原文基线的事实召回差决定。

## 8. SQLite 存储

### 8.1 核心表

```text
books
volumes
chapters
raw_chunks
extraction_runs
run_checkpoints
compression_segments
entities
entity_mentions
entity_alias_claims
entity_merge_audit
claims
claim_observations
relation_claims
event_claims
event_participants
state_claims
org_claims
foreshadow_claims
terms
term_definition_claims
claim_evidence
event_links
state_catalog
ontology_versions
summary_artifacts
embedding_records
```

FTS 虚表索引规范化原文和必要的结构化摘要；向量虚表只保存向量和稳定 record ID，元数据保存在普通表。每次检索必须先限定 `book_id`；若向量后端不能在 Top-K 前执行元数据过滤，则按 book/profile 分表，避免其他书的候选占满 Top-K。不同向量维数使用独立虚表，不能混存。

索引策略（P0 DDL 落实）：`observed_ordinal`（知识截止过滤）、`claim_version_id` 与 `supersedes_version_id`（版本链）、`event_links(source_event_id/target_event_id)`（因果递归）、`event_participants(entity_id/event_id)`（实体到事件）、`entity_mentions(surface_name)`（消歧）必建；复合索引按 §11 查询路线逐条覆盖，避免扫描全表。

### 8.2 写入模型

- 8–16 个抽取 worker 输出 Draft；
- 单 writer 消费有界队列并批量事务写入 staging 表；
- 开启 WAL 和 busy timeout；
- 每个 run 记录输入 hash、配置版本和状态；
- 唯一约束保证幂等；
- Canonical、证据和索引完成后原子激活 run；
- 失败 run 不进入默认查询视图；
- 章节级 checkpoint：每章 Map 产物落 staging 后即持久化；checkpoint 唯一键为 `(book_id, chapter_id, content_hash, pipeline_version, prompt_version, compression_version, schema_version)`。中断后仅复用唯一键完全一致的成功结果；任一输入或配置变化都必须重跑；
- LLM 调用治理：全局令牌桶限流（QPS/并发上限按模型档配置）、指数退避重试、超时上限与最大重试次数；不可重试错误（schema/输入无效）直接标记失败不重试；
- 数据库迁移和全量重建前执行备份。

## 9. 消歧与事件链接

### 9.1 实体消歧

处理顺序：

1. 名称规范化和泛称过滤；
2. 精确别名与规则合并；
3. 基于同章共现、属性和上下文生成候选；
4. 仅对低置信候选进行语义判定；
5. 写入 merge/split 审计记录；
6. 重写 mention 到 canonical ID 的映射。

`knowledge_cutoff_chapter` 查询时，展示名称只能来自截止章节前已披露的 alias claim，不能直接展示全书最终 canonical 名称。

### 9.2 EventLinker

候选事件根据参与者、地点、时间窗口、局部因果和 cause_candidates 阻塞。高置信规则直接链接，低置信候选进入语义判定。

因果边的 `observed_ordinal` 等于全部支持证据的最大披露章节。未形成证据的边保持 unverified，不进入默认因果回答。

## 10. Reduce

卷分组规则（分层 Reduce 的中间层输入边界）：

- 优先使用原书卷标题（EPUB 目录或章节标题中的卷标记）；
- 缺失时按固定章节数分组（默认 50 章/卷）；
- `volume_id` 使用持久化 UUID，不由卷序生成；`volumes` 记录来源、边界章节、ordinal、grouping_version 和 content_hash；
- 章节插入、重排或分组规则变化时生成新的 grouping version，旧卷摘要保留但失效，按新边界重建。

默认采用分层 Reduce：

```text
章节结构化记忆
  → 卷摘要
  → 全书摘要
```

摘要产物保存：输入 claim 版本集合、生成配置版本、内容 hash 和 `max_observed_ordinal`。输入事实变化时标记失效并按依赖关系重建。

主线剧情首期由 event claims、event_links 和全书摘要派生，不建立独立 plot thread 表。若 Pilot 证明主线检索不稳定，再增加 `plot_threads` 和 `event_thread_membership`。

## 11. 查询

### 11.1 查询路线

| 类型 | 路线 |
|---|---|
| 实体状态 | state claim 按知识截止时间过滤，再按世界有效时间选择版本 |
| 一跳关系 | relation claim 索引查询 |
| 势力成员 | org event 日志折叠 |
| 关系演变 | relation 版本按时间排序 |
| 因果链 | event_links 递归 CTE |
| 原文细节 | FTS + 向量检索，RRF 融合 |
| 术语释义 | `terms` 表直查（功法/宝物/设定名词释义） |
| 按章节图谱 | 分别应用知识截止过滤和世界有效时间过滤 |
| 全局主线 | 分层摘要 + 关键事件检索 |

结构化查询优先；无法直接回答时再进入混合检索与生成式合成。所有回答返回 evidence 和章节定位。

### 11.2 因果查询

- 入口支持实体→事件：先由 `event_participants(entity_id, event_id, role)` 索引表或 org 归属聚合到关联事件，再从这些事件沿 event_links 展开（一跳到多跳）；
- 最大深度默认 5；
- visited 集合防止环；
- 路径置信度为各边置信度乘积；
- 多路径按置信度和证据覆盖率排序；
- rejected、contested 和无支持证据的边默认排除。

### 11.3 查询时间参数

查询使用两个相互独立的可选参数：

```text
knowledge_cutoff_chapter  读者最多知道哪一章，过滤 observed 时间
world_at_chapter          查询故事世界在何时成立的状态，过滤 world_valid 时间
```

传入 `knowledge_cutoff_chapter=N` 后：

- 原文 chunk 限制为 `observed_ordinal <= N`；
- claim、alias 和 event link 按各自 `observed_ordinal <= N` 过滤；摘要等派生产物按 `max_observed_ordinal <= N` 过滤；
- 因果链任意一跳不可见时截断该分支；
- 合成阶段只能接收过滤后的上下文；
- 实体展示名只能来自截止章节前已披露的 alias claim；
- 缓存键必须包含 N。

传入 `world_at_chapter=M` 后，关系、状态、势力和图谱边按 `world_valid_from <= M` 且 `world_valid_to` 为空或大于 M 过滤。`world_valid_kind=unknown` 的事实不得伪装成精确世界状态，可单独作为“时间不确定”结果返回。

两个参数可以同时使用，但不得合并为同一个 SQL 条件。该模式实现披露章节截断和世界状态回放，不实现角色之间不同知识权限。

## 12. Token 预算

以下为 700 万中文字、约 2000 章的初始容量估算。以 `T_src` 表示规范化原文 token 数，预计 `T_src = 700万–1000万`。实际值必须在 P0 用生产 tokenizer 统计。

### 12.1 单次调用预算

| 环节 | 单次输入 | 单次输出 |
|---|---:|---:|
| 压缩段 | 1,500–4,000 tokens | 输入的 50%–90% |
| 单章 Map | 2,000–8,000 tokens，另加固定 schema prompt | 400–1,200 tokens |
| 消歧候选批次 | 2,000–8,000 tokens | 200–800 tokens |
| EventLinker 候选批次 | 2,000–8,000 tokens | 200–800 tokens |
| 证据验证批次 | 2,000–8,000 tokens | 100–500 tokens |
| 卷 Reduce | 20,000–120,000 tokens | 2,000–8,000 tokens |
| 单次问答 | 5,000–20,000 tokens | 500–2,000 tokens |

### 12.2 全量建库预算

设压缩输出比例为 `r=0.5–0.9`，每章固定 prompt 为 `P`，章节数为 `C≈2000`：

```text
压缩输入     ≈ T_src
压缩输出     ≈ r × T_src
Map 输入     ≈ r × T_src + P × C
Map 输出     ≈ 80万–240万 tokens
消歧/链接/验证输入 ≈ 100万–400万 tokens
Reduce 输入  ≈ 50万–150万 tokens
```

预计离线处理总输入为 1300万–2700万 tokens，总输出为 440万–1200万 tokens。压缩关闭时取消压缩调用，Map 直接读取原文；总输入重新按实际 prompt 开销计算。

每次调用必须记录 input、cached input、reasoning、output、retry 和 discarded tokens。P1 使用实测 Token 数据替换本节区间。

## 14. 评测与验收

### 14.1 P0 数据契约

- 规范化文本和证据 offset 往返成功率 100%；
- raw chunk 覆盖原文且无非预期空洞；
- JSON Schema 和 SQLite 约束覆盖全部事实类型；
- 同输入重复运行不产生重复 fact/version/evidence；
- 相同 payload 在不同 run 中复用同一 claim version，只新增 observation；状态值变化复用同一 fact_id 并新增 version；
- checkpoint 仅在全部键一致时命中，任一内容或配置版本变化均失效；
- 外键和 primary evidence 引用完整率 100%；
- 中文 FTS 切分方案通过专名与原句检索集；
- 多书检索不返回其他 book_id 的结果，向量 Top-K 不受其他书候选挤占；
- Token 计量覆盖所有模型调用。

### 14.2 P1 短篇整本 Pilot

使用约 30 万字完整小说，比较原文 hybrid 基线、结构化管线和可选压缩管线。初始验收线：

- 核心实体合并 F1 ≥ 0.90；
- 全部实体合并 F1 ≥ 0.85；
- 事实 precision ≥ 0.90，recall ≥ 0.80；
- 直接证据 span hash 复现率 100%；
- QA 引用章节正确率 ≥ 0.95；
- 因果边 precision ≥ 0.85；
- 压缩线事实 recall 相对原文线下降不超过 0.02；
- 全链路失败任务可重试，完成后无部分激活 run；
- 输出完整 Token 账本和每万字吞吐数据。

### 14.3 P2 长篇质量 Pilot

使用连续 200–300 章主样本，并增加开头、中段和结尾窗口。人工标注跨百章实体、状态和因果线程，验证：

- 后期身份揭示后的 canonical 合并；
- `knowledge_cutoff_chapter` 不泄露后期别名和摘要；`world_at_chapter` 与知识截止参数分别通过独立测试；
- 长程状态更新与关系演变；
- 因果链断裂率和链式问答正确率；
- 卷级和全书摘要的事实覆盖率；
- 数据库、索引、队列和服务吞吐的线性扩展性。

验收阈值在标注集冻结前写入测试配置，不得在看到结果后修改。
