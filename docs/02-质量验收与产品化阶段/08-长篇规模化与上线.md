# 08 长篇规模化与上线

> 优先级：P2  
> 状态：尚未开始

## 目标

在短篇质量门通过后验证中等规模和超长篇运行，解决向量检索性能、断点恢复、成本、持续回归和产品部署问题。

## 建议实施顺序

1. 冻结已通过质量门的模型、prompt、Schema、verifier 和 embedding profile。
2. 选取 200–300 章样本运行 P2 Pilot，评估质量漂移、吞吐、成本和查询延迟。
3. 在样本规模复核阶段 07 的向量存储选型和 p95 性能门，必要时完成切换及索引重建。
4. 验证索引和流水线的断点、重试、增量更新、备份与恢复。
5. 中等规模验收通过后，再运行完整长篇。
6. 验证黄金集持续回归、运行监控和发布回滚流程能够覆盖全量数据。

## 配套任务

- 使用阶段 07 已完成的 `inspect`、运行状态和失败清理能力；
- 建立容量、LLM 与 embedding 成本预测；
- 前端提供运行状态、索引状态和数据版本信息；
- 对外部署时补充鉴权、限流、日志、API 版本和监控。

## 退出条件

- 中等规模 Pilot 通过质量、成本、吞吐和 p95 查询延迟门。
- 全量运行可恢复，不因单章或单请求失败整体重来。
- 全量数据库和索引经过完整性检查、备份及回归评测。
- 产品入口、运行手册和故障处理流程可由非开发者执行。
