# 07 运维、性能与持续回归

> 优先级：P1/P2  
> 状态：备份、恢复、完整性扫描和 fixture CI 已有；关键生产能力未闭环

## 目标

补齐阶段一遗留的检查、性能和持续回归能力，使真实数据运行状态可见，长篇前的存储/检索性能可量化，质量变化可以自动发现。

## 阶段一明确结转项

### 1. 实现 `inspect` CLI

当前命令仍返回“尚未实现”。至少应支持：

- 图书、章节数和输入 hash；
- extraction run 状态、阶段、失败原因和 active 版本；
- active index、embedding profile、维数和记录数；
- claim/evidence/entity/event/link/summary 数量及验证版本；
- running/failed/abandoned run 和完整性异常提示；
- 机器可读 JSON 输出，供脚本和前端状态页复用。

### 2. 生产向量检索性能

真实 embedding adapter 当前仍配合 `BruteForceVectorStore` 全扫描。需要在短篇和 200–300 章样本上记录索引体积、候选数和 p50/p95 延迟，再决定保持现状还是把 production factory 切到 `SqliteVecVectorStore`。切换必须验证 profile、维数、metadata 过滤、重建和回滚。

### 3. 人工黄金持续回归

当前 CI 运行 fixture 评测，不能代替《百年孤独》人工黄金集。黄金集冻结后需建立可控的离线/定期回归，按 Map、证据、实体、因果、检索、合成和摘要分别报告，避免外部模型调用成为普通无密钥 CI 的硬依赖。

### 4. 运行与产品观测

- 查询路线、延迟、错误率、token 和成本；
- Map/摘要/压缩的调用、重试、失败和费用；
- 数据库容量、WAL、索引状态和备份新鲜度；
- API/CLI 对同一查询的事实集一致性；
- cutoff 泄露和证据 hash 的定期扫描；
- 运行状态 API/前端管理视图。

## 退出条件

- `inspect` 不再是占位，关键对象和异常可被人及脚本检查。
- 生产向量后端经过可复现压测并形成带阈值的选型结论。
- 人工黄金集进入版本化定期回归，失败可定位到具体质量层。
- 备份、恢复、索引重建和失败重跑完成真实数据演练。
- 质量、成本、吞吐、延迟和错误率形成持续可观察基线。
