# 01 工程骨架

## 目标

建立一个可安装、可测试、可配置、可从命令行运行的最小工程。此阶段只确定模块边界和基础约束，不实现模型抽取业务。

## 前置条件

- 《定版方案》是当前实现契约。
- 确定首选实现语言、包管理方式和最低运行时版本。
- 明确 SQLite 作为唯一权威数据源。

## 任务

### 1. 初始化项目

- 建立源码包、测试目录、迁移目录和 fixture 目录。
- 配置格式化、静态检查、类型检查和单元测试。
- 提供开发环境安装和测试命令。
- 增加最小 CI：安装、静态检查、单元测试。

建议模块边界：

~~~text
src/novelcanon/
  config/
  ingestion/
  storage/
  schemas/
  pipeline/
  extraction/
  resolution/
  events/
  evidence/
  retrieval/
  query/
  summaries/
tests/
fixtures/
migrations/
~~~

### 2. 建立配置入口

- 区分应用配置、generation profile、embedding profile。
- 支持从配置文件和环境变量加载非敏感参数。
- 密钥只从安全环境读取，不写入配置快照、日志或数据库。
- 为所有配置生成稳定 config hash。
- 启动时校验配置，不允许静默使用不完整默认值。

### 3. 建立统一 CLI

先定义命令边界，未实现的命令可以明确返回“尚未实现”：

~~~text
novelcanon import
novelcanon index
novelcanon extract
novelcanon activate
novelcanon query
novelcanon inspect
~~~

CLI 只负责参数解析和调用 application service，不直接编写 SQL 或业务逻辑。未来 API 与 CLI 应复用同一 service 层。

### 4. 建立可观测性

- 使用结构化日志。
- 每条流水线日志包含 book_id、run_id、chapter_id（适用时）。
- 错误日志保留错误类型、阶段和可重试标志。
- 不记录完整原文、模型密钥或无上限的模型响应。

### 5. 记录关键技术选择

至少建立以下 ADR：

- 运行时和包管理；
- SQLite 访问方式与 migration 工具；
- Schema/序列化方案；
- CLI 框架；
- 测试和 fixture 策略；
- 向量扩展的抽象边界。

## 产物

- 可安装的源码包；
- 可执行 CLI；
- 基础配置模型；
- CI 和质量检查配置；
- 一组 ADR；
- 至少一个 smoke test。

## 验证

- 新环境可以按 README 一次完成安装。
- CLI 能显示帮助和版本。
- 测试可在无网络、无模型密钥时运行。
- 无效配置在启动阶段失败，并给出明确字段错误。
- 日志能够关联一次命令执行，但不泄露敏感信息。

## 退出标准

- 本地和 CI 的静态检查、类型检查、测试全部通过。
- 核心模块之间没有循环依赖。
- 后续阶段可以在不改入口结构的前提下新增实现。
- 工程运行不依赖任何真实模型或外部服务。

## 暂不实现

- 真实抽取 prompt；
- 远程模型调用；
- Web API；
- 大规模并发；
- 图数据库或图算法。
