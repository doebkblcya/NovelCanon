# 10 查询、检索与分层摘要

## 目标

建立结构化查询优先、混合检索兜底、所有回答带证据的查询层，并生成可失效重建的卷级和全书摘要。

## 前置条件

- active claim、evidence、canonical entity 和 event link 可用。
- FTS 可稳定检索原文。
- embedding profile 和索引版本机制可用。
- 双时间过滤器已通过安全测试。

## 查询路线

按问题类型显式路由：

| 类型 | 首选路线 |
|---|---|
| 实体状态 | state claim + 双时间过滤 |
| 一跳关系 | relation claim |
| 势力成员 | org 日志折叠 |
| 关系演变 | claim 版本时间序列 |
| 因果链 | event link 递归 CTE |
| 原文细节 | FTS + 向量 + RRF |
| 术语释义 | term definition claim |
| 按章图谱 | claim 双时间过滤 |
| 全局主线 | 分层摘要 + 关键事件 |

不应把所有问题都先转换成向量检索。

## 实施顺序

### 1. 结构化 repository/query service

- 每条路线都强制 book_id。
- 时间过滤在 repository 层应用。
- 返回对象统一包含事实版本、置信度、状态和 evidence。
- 提供 explain/diagnostic 信息，便于验证实际命中路线。

### 2. 向量检索

- 运行时验证 profile 和维数。
- Top-K 前完成 book/profile 隔离。
- 记录 record ID，再从普通表读取元数据。
- 索引版本切换与 raw chunk 一致。

### 3. RRF 融合

- FTS 与向量各自产生候选和排名。
- 使用版本化 RRF 参数融合。
- 在融合前应用 book/cutoff 过滤。
- 去重基于稳定 raw chunk ID 或规范化 source span。
- 保存各路线贡献，方便评测和诊断。

### 4. 答案合成

模型只能接收过滤后的上下文。答案必须：

- 区分原文事实和推断；
- 返回章节定位与 evidence；
- 在证据不足时明确拒答或表达不确定；
- 不使用模型自身记忆补充小说内容；
- 记录 query profile、上下文 ID 和 cutoff 参数。

### 5. 缓存

缓存键至少包含：

- book_id；
- 标准化查询；
- knowledge cutoff；
- world at chapter；
- active run/index version；
- query/synthesis profile。

active run 或依赖版本改变后，旧缓存不能继续返回。

### 6. 卷分组

- 优先原书卷标题。
- 缺失时默认每 50 章分组。
- volume_id 使用持久化 UUID。
- 保存来源、边界、ordinal、grouping version 和 content hash。
- 分组变化生成新版本并使旧摘要失效。

### 7. 分层 Reduce

~~~text
章节结构化记忆
  -> 卷摘要
  -> 全书摘要
~~~

每个摘要保存：

- 输入 claim version 集合；
- generation/profile/prompt 版本；
- content hash；
- max observed ordinal；
- 依赖的下级摘要版本。

输入事实变化时按依赖图标记失效并重建。

## 产物

- query router；
- 结构化查询服务；
- vector/RRF retrieval；
- evidence-grounded synthesis；
- cache/version policy；
- volume grouper；
- hierarchical reducer；
- 查询与摘要评测集。

## 验证

- 结构化可回答的问题不会无故落到生成式检索。
- 多书、cutoff 和 world time 过滤在所有路线一致。
- FTS、向量和 RRF 可分别评测。
- 开发查询集达到预先冻结的引用章节正确率阈值，正式指标在阶段 11 的 P1 中验收。
- 摘要 max observed ordinal 正确。
- 输入 claim 变化会使依赖摘要和缓存失效。

## 退出标准

- 主要查询类型均有确定路由和证据返回。
- 生成式合成无法访问过滤前上下文。
- 卷和全书摘要可重建且不会泄露 cutoff 后内容。
- 查询质量、延迟和 Token 消耗可按路线统计。

## 实现记录（阶段 10 交付）

### 版本与模块

- 路由：`query/router.py`（ROUTER_VERSION="router-v1"）——9 类问题确定性关键词路由，
  每类映射首选路线（structured/hybrid/summary），explain 记录命中关键词；未匹配显式
  fallback 到混合检索并标注。强原文信号（原文/原话/写道…）优先于章节位置。
- 结构化查询：`query/service.py` 扩展 term_definition / org_membership（org 日志折叠：
  join/found/promote/demote 为当前成员，leave/dissolve 结束）/ chapter_graph /
  entity_snapshot / entity_events；返回统一含 claim_status/confidence/evidence。
- 检索：`retrieval/service.py`（运行时 profile/维数验证、book 隔离、record ID → 普通表
  元数据回读、索引版本切换后孤儿 chunk 防御跳过）+ `retrieval/rrf.py`
  （RRF_PARAMS_VERSION="rrf-v1"，k=60 版本化，跨路线去重按 raw_chunk_id，route_ranks 诊断）。
- 缓存：`query/cache.py`（CACHE_POLICY_VERSION="cache-v1"）——键含 book_id/标准化查询/
  query type/cutoff/world_at/active run 集合签名/active index version/query+synthesis
  profile；active run 或索引版本变化 → 签名变化 → 旧缓存不命中。
- 合成：`query/synthesis.py`（SYNTHESIS_SCHEMA_VERSION="synthesis-v1"）——prompt 只含
  过滤后上下文（结构上无法访问过滤前全文）；无模型走确定性模板；证据不足拒答；
  记录 context_id（上下文 hash）/query profile/cutoff/world_at。
- 执行：`query/executor.py`——ask() 串起路由→执行→缓存→合成，按路线统计
  （calls/延迟/上下文项/命中/缓存命中）。
- 卷分组：`summaries/volumes.py`（GROUPING_VERSION="grouping-v1"）——优先原书卷标题
  （source），缺失默认每 50 章（default）；volume_id 持久化 UUID；保存来源/边界/ordinal/
  grouping version/content hash；分组变化生成新版本并使旧卷摘要失效；幂等（内容未变复用）。
- 分层 Reduce：`summaries/reducer.py`（REDUCER_SCHEMA_VERSION="reducer-v1"）——章节结构化
  记忆 → 卷摘要 → 全书摘要；每级保存输入 claim 版本集合/depends_on_summaries/
  generation/profile/prompt 版本/content hash/max observed ordinal；输入变化 → 新版本 +
  旧行 stale + 按依赖图重建；DeterministicSummarizer（无模型提取式）与 LLMSummarizer 可选。
- 迁移：0014（query_cache / summary_artifacts / volumes.grouping_source）。

### 关键决策

1. **embedding_profile_id 语义**：index_versions.embedding_profile_id 与
   embedding_records.profile_id 存 embedder.profile_id（embedding 模型身份），不再存
   vector_store.profile_id；查询侧 _verify_profile 校验
   index.embedding_profile_id == embedder.profile_id 且维数一致。
2. **RRF 只看排名不看分数**：规避 BruteForce（余弦相似度，越大越好）与 sqlite-vec
   （distance，越小越好）的尺度差异；向量候选无法在 vec0 内按 ordinal 过滤，融合前在
   Python 侧按元数据做 cutoff 过滤。
3. **分组来源稳定**：分组重建会把 chapters.volume_id 指向新卷行——detect_source 优先
   用现有分组的 grouping_source（保持来源），首次分组才看导入时 volume_id 引用。
4. **摘要幂等判定按输入集合**：同 scope 已有 valid 且 input_claim_versions/depends/
   prompt_version 一致 → 复用（不重跑模型，避免 LLM 内容漂移触发重建）；
   summary_id = hash(book, level, scope, content_hash)，内容变化 → 新 id → 旧行 stale。
5. **缓存失效**：active run 集合（run_id+status）与 active index version 的签名入键，
   同状态幂等（不依赖时间戳）。

### 验证对照

- 结构化可回答问题（实体状态/关系/势力/演变/因果/术语/按章）均路由到 structured，
  带证据返回，不落混合检索（test_query_router/test_executor）。
- 多书、cutoff、world time 过滤在所有路线一致（test_query_service10 双时间矩阵）。
- FTS/向量/RRF 分别可评测（test_rrf/test_retrieval_service：profile 不匹配拒绝、
  book 隔离、cutoff 融合前过滤、路线贡献诊断）。
- 摘要 max observed ordinal 正确（0 基 ordinal；cutoff 过滤输入，不泄露其后内容）。
- 输入 claim 变化 → 依赖摘要和缓存失效（test_summaries/test_query_cache）。
- 缓存键版本化：active run/索引变化后旧缓存不返回（test_query_cache）。
- 开发查询集：路由与合成测试覆盖 9 类问题；引用章节正确率的正式指标按文档约定在
  阶段 11 的 P1 中验收（开发查询集冻结于 tests/test_executor.py / test_query_router.py）。

### 复审闭环（阶段 10 验收阻断问题）

1. **[P0] 全书摘要真分层**：Summarizer 接口扩展 volume_summaries 输入——book 级摘要的
   生成输入是卷摘要内容（memories 只作元数据），LLM prompt 不再展开章节记忆；
   DeterministicSummarizer 转述各卷摘要；DETERMINISTIC_PROMPT_VERSION=v2（生成逻辑
   变化 → 幂等判定失效 → 重建）。
2. **[P0] 实体状态 world_at**：ENTITY_STATE 路线 world_at 传入时切换到 world_state_at；
   entity_snapshot 同步（world_at 非 None 用世界时间快照）。
3. **[P0] cutoff 端到端**：_find_entity 的 alias 按 observed_ordinal 截断（后期化名不
   穿透早期查询）；claim_history 新增 knowledge_cutoff（关系演变版本数截止前）。
4. **[P0] 证据定位**：_claim_item 保留第一条 supports 证据的
   chapter_id/char_start/char_end/stance；_term/_chapter 复用 _claim_item，
   AnswerSource 满足「章节定位 + evidence」退出标准。
5. **[P1] 缓存与 Token**：
   - active_state_signature 纳入 valid 摘要集合（摘要重建 → 主线缓存失效）；
   - LLM 问答/Reduce 的 usage 不再丢弃——AnswerResult.usage、SummaryResult.tokens、
     RouteStats.input/output_tokens，CLI query/summarize 输出 token 统计；
   - 无摘要主线回退改 all_events（cutoff 前全书关键事件，非仅第 0 章）。

每项均有 QueryExecutor 端到端回归测试（tests/test_executor.py、test_query_cache.py、
test_summaries.py）。

### 复审闭环（第二轮）

1. **[P0] 因果链真实证据定位**：causal_paths/causal_results 的递归 CTE 携带
   edges（因果边 claim_version_id 序列），新增 _link_evidence_map 解析
   event_link_verifications.verification_evidence（chapter_id/span/原文），
   Python 侧补章节 ordinal；executor 因果路线用**第一条边的版本与定位**作
   AnswerSource（不再是起始事件或路径深度）。
2. **[P0] 关系演变版本时间序列**：
   - claim_history 经 claim_observations + active extraction_runs 限定
     （失败/失效 run 的版本不计数）；
   - 新增 relation_evolution(fact_id, cutoff)：每版本返回 operation/状态/
     observed 章节/relation payload/证据，executor 逐版本输出
     assert/update/retract 的实际变化。
3. **[P1] Token 持久化**：migration 0015 使 token_ledger.run_id 可空；
   QueryExecutor 的 LLM usage 写 stage='query' 账本；RouteStats 补
   cached/reasoning/retry/discarded 全字段；LLM Reduce usage 已在
   SummaryResult.tokens。
4. **[P1] reducer 元数据**：恢复「内容相同」的历史摘要时补全
   content_hash/max_observed_ordinal/generation_profile_id/schema_version；
   幂等复用判定比较 profile 与 schema。
5. **[P1] 事件当前版本**：all_events/entity_events 按 fact_id 取最新版本
   （rn=1 + 非 retract）——被 supersede 的旧事件不进入主线回退。

### 复审闭环（第三轮）

1. **[P0] 多跳因果链全部边进来源**：ContextItem 新增 extra_evidence（多证据
   定位），AnswerResult.sources 逐条展开——多跳路径（A→B→C）的每条边都有
   claim_version_id/章节/span 引用，回答声称的每条因果关系都有证据。
2. **[P0] 已结束关系可查演变**：新增 relation_facts_for_entity——从 active
   run 的**历史** relation 版本按实体枚举 fact（不要求当前 supported/非
   retract），再逐 fact 调 relation_evolution；最新版本 retract 的关系也能
   展示「建立 → 结束」完整时间线（不再因入口 one_hop_relations 排除而拒答）。
3. **[P0] 事件当前版本过滤顺序**：all_events/entity_events 的
   claim_status='supported' 过滤移到 rn=1 外层——最新 contested/rejected
   版本不会被提前移除，旧 supported 版本不会错误回退；entity_events 的
   参与者匹配同步移到外层（内层 JOIN participants 会过滤无参与者的新版本，
   同样导致旧版回退）。
4. **[P1] summary token 账本**：HierarchicalReducer 每次 LLM 摘要的 usage
   写入 token_ledger（stage='summary'，run_id 可空）——query 与 summary 两
   类账本均持久化，不再只在内存汇总。

新增回归：多跳路径边集合覆盖（test_executor）、retract 关系演变含结束版本
（test_executor）、contested 不回退（test_query_service10）、summary 账本
（test_summaries）。全量 276 测试通过。
