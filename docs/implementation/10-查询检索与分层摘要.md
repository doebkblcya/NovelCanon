# 10 查询、检索与分层摘要

## 目标

建立结构化查询优先、混合检索兜底、所有回答带证据的查询层，并生成可失效重建的卷级和全书摘要。

## 前置条件

- active claim、evidence、canonical entity 和 event link 可用。
- FTS 可稳定检索原文。
- embedding profile 和索引版本机制可用。
- 双时间过滤器已通过安全测试。

## 查询路线

按问题类型显式路由：

| 类型 | 首选路线 |
|---|---|
| 实体状态 | state claim + 双时间过滤 |
| 一跳关系 | relation claim |
| 势力成员 | org 日志折叠 |
| 关系演变 | claim 版本时间序列 |
| 因果链 | event link 递归 CTE |
| 原文细节 | FTS + 向量 + RRF |
| 术语释义 | term definition claim |
| 按章图谱 | claim 双时间过滤 |
| 全局主线 | 分层摘要 + 关键事件 |

不应把所有问题都先转换成向量检索。

## 实施顺序

### 1. 结构化 repository/query service

- 每条路线都强制 book_id。
- 时间过滤在 repository 层应用。
- 返回对象统一包含事实版本、置信度、状态和 evidence。
- 提供 explain/diagnostic 信息，便于验证实际命中路线。

### 2. 向量检索

- 运行时验证 profile 和维数。
- Top-K 前完成 book/profile 隔离。
- 记录 record ID，再从普通表读取元数据。
- 索引版本切换与 raw chunk 一致。

### 3. RRF 融合

- FTS 与向量各自产生候选和排名。
- 使用版本化 RRF 参数融合。
- 在融合前应用 book/cutoff 过滤。
- 去重基于稳定 raw chunk ID 或规范化 source span。
- 保存各路线贡献，方便评测和诊断。

### 4. 答案合成

模型只能接收过滤后的上下文。答案必须：

- 区分原文事实和推断；
- 返回章节定位与 evidence；
- 在证据不足时明确拒答或表达不确定；
- 不使用模型自身记忆补充小说内容；
- 记录 query profile、上下文 ID 和 cutoff 参数。

### 5. 缓存

缓存键至少包含：

- book_id；
- 标准化查询；
- knowledge cutoff；
- world at chapter；
- active run/index version；
- query/synthesis profile。

active run 或依赖版本改变后，旧缓存不能继续返回。

### 6. 卷分组

- 优先原书卷标题。
- 缺失时默认每 50 章分组。
- volume_id 使用持久化 UUID。
- 保存来源、边界、ordinal、grouping version 和 content hash。
- 分组变化生成新版本并使旧摘要失效。

### 7. 分层 Reduce

~~~text
章节结构化记忆
  -> 卷摘要
  -> 全书摘要
~~~

每个摘要保存：

- 输入 claim version 集合；
- generation/profile/prompt 版本；
- content hash；
- max observed ordinal；
- 依赖的下级摘要版本。

输入事实变化时按依赖图标记失效并重建。

## 产物

- query router；
- 结构化查询服务；
- vector/RRF retrieval；
- evidence-grounded synthesis；
- cache/version policy；
- volume grouper；
- hierarchical reducer；
- 查询与摘要评测集。

## 验证

- 结构化可回答的问题不会无故落到生成式检索。
- 多书、cutoff 和 world time 过滤在所有路线一致。
- FTS、向量和 RRF 可分别评测。
- 开发查询集达到预先冻结的引用章节正确率阈值，正式指标在阶段 11 的 P1 中验收。
- 摘要 max observed ordinal 正确。
- 输入 claim 变化会使依赖摘要和缓存失效。

## 退出标准

- 主要查询类型均有确定路由和证据返回。
- 生成式合成无法访问过滤前上下文。
- 卷和全书摘要可重建且不会泄露 cutoff 后内容。
- 查询质量、延迟和 Token 消耗可按路线统计。
