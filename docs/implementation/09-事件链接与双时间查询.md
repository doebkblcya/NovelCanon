# 09 事件链接与双时间查询

## 目标

建立可验证的跨章事件因果链接，并分别实现“读者知道什么”和“故事世界何时成立”的时间查询。

## 前置条件

- event claims 和 event participants 已 canonical 化。
- 证据验证链可用。
- observed ordinal 已覆盖 claim、alias、evidence 和派生产物。
- world_valid 字段和枚举已写入数据契约。

## 实施顺序

### 1. 全局事件标识

- 将章内 local_event_id 映射为 global_event_id。
- event fact_id 使用事件类型、参与者、地点、章节锚点和章内序号等稳定信息。
- Event payload 不复制 participants、causes 或 results。
- 事件修订遵循普通 claim append-only 版本规则。

### 2. 候选阻塞

跨章候选基于：

- 参与者交集；
- 地点；
- 时间窗口；
- local causes；
- cause_candidates；
- 事件类型兼容性；
- 叙事距离和 narrative weight。

候选生成应有召回率评测，不能只观察最终精度。

### 3. EventLinker

- 高置信规则直接生成候选链接。
- 低置信候选进入受约束语义判定。
- relation_type 只允许 causes、enables、prevents。
- results 通过 causes 的反向查询得到。
- 无支持证据的链接保持 unverified。

### 4. 因果证据与可见时间

- 默认保存原因端和结果端 evidence。
- event link 的 observed ordinal 等于全部支持证据的最大披露章节。
- 任一端证据在 cutoff 后不可见时，该边不可用于回答。
- contested、rejected 和无支持证据的边默认排除。

**边支持性（验收 P0 收紧）**：规则层（参与者交集 + 时间先后）只生成
candidate——端点各自有证据不等于边有因果证据（「甲吃早饭」→「甲中彩票」
同参与者同先后不能证明因果）。

**LinkVerifier（验收 P0 交付）**：边要 supported 必须有**关系证据**——
目标章原文同一句同时出现「源事件动作/摘要锚点」（event_type / summary，
**不含参与者**——参与者共现是候选前置条件）与「强因果连接词」（因此/
于是/所以/从而/导致/使得/由此/因而/以致/促使/引发/促成/因为/之所以；
**纯时间词如之后/随后/终于不作为因果充分条件**）。验证通过 → supported +
落库 verification_method（causal-connective）与原文证据 span（可审计）；
否则保持 unverified。

**验证结果 run 作用域（验收 P0）**：event link 版本 ID 只由 fact/payload
决定，多 run 共享同一条边。验证结果存入 event_link_verifications
（claim_version_id, extraction_run_id, claim_status, method, evidence）——
每个 run 对每条边的验证结论独立；causal_paths / causal_results 经
**active run** 的 observation 关联该 run 的验证行。未激活 run 重新链接
并验证失败时，**不得改写 active 查询结果**（激活隔离）。

**supported ⇒ 关系证据硬约束（验收 P0）**：claim_status='supported' 的
验证行必须同时携带 verification_method 与 verification_evidence（非空，
数据库 CHECK 兜底）——调用方仅凭 envelope 状态声称 supported 会被降级为
unverified；外部验证必须提供方法与可审计证据。迁移回填按
event_link_observations（成员关系是复用的真相）为每个 (link, run) 补验证
行，存量 supported 且缺证据的降级为 unverified——复用边的 active run
升级后不丢可见性。

### 5. 因果递归查询

- 实体先通过 event_participants 或 org 聚合进入事件。
- 使用递归 CTE 沿 event_links 展开。
- 默认最大深度为 5。
- visited 集合阻止环。
- 路径置信度为边置信度乘积。
- 多路径按置信度和证据覆盖率排序。

### 6. knowledge cutoff

过滤所有进入合成上下文的数据：

- raw chunk；
- claim 和 alias；
- event link；
- summary artifact；
- 查询缓存。

因果链某一跳不可见时截断该分支。缓存键必须包含 cutoff。

### 7. world at chapter

关系、状态、势力和图谱边按 world_valid 区间过滤。

- story_time：可以按确定世界时间处理；
- chapter_proxy：明确标注为章节近似；
- unknown：只能作为时间不确定结果返回。

knowledge cutoff 与 world at chapter 必须通过两个独立的查询参数、过滤器和测试矩阵实现，不能合并成一个 SQL 条件。

**双时间组合（验收 P0 收紧）**：world_at 与 knowledge_cutoff 两个独立
参数必须在同一查询（world_state_at）中同时进入过滤——「世界时间从第
1 章成立、但第 10 章才通过回忆披露」的事实，读者 cutoff=5 时不得看到
（observed_ordinal <= cutoff 必须成立）。两个参数互不替代、组合生效，
测试矩阵覆盖「世界窗口通过但读者未到披露点」「读者已到披露点」「世界
窗口未开始但读者已到」三象限。

**world-valid 查询面（验收 P1 扩展）**：world_valid 过滤覆盖全部事实
类型——state（world_state_at）、relations（one_hop_relations 增加
world_at 参数，与 knowledge_cutoff 组合）、org（org_state_at 提供
势力/成员世界状态查询，story_time 区间 / chapter_proxy / unknown
排除 / cutoff 组合）、图谱边（event link 写入 world_valid，默认
chapter_proxy = 最大证据披露章节；causal_paths / causal_results 增加
world_at 参数，与 knowledge_cutoff 双参数同时过滤）。

## 产物

- global event mapper；
- EventLinker candidate generator；
- link verifier；
- recursive causal query；
- observed/world-valid filters；
- 时间安全测试矩阵；
- 因果评测集。

## 验证

- event participant 和 event link 引用完整。
- results 反向查询与 causes 正向结果一致。
- 环形事件图不会导致无限递归。
- 路径置信度计算正确。
- cutoff 隐藏任意一跳时对应路径被截断。
- unknown world time 不会被表达为精确状态。
- 两个时间参数组合查询的结果符合人工期望。

## 退出标准

- 开发标注集达到预先冻结的阶段阈值；正式因果边 precision 在阶段 11 的 P1 中验收。
- 所有默认因果回答都有完整支持证据。
- 后期链接、别名和摘要无法通过早期 cutoff 泄露。
- 双时间测试成为每次数据/查询改动的强制回归项。
