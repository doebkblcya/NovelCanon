# 04 可恢复流水线

## 目标

建立适合长篇离线处理的运行框架，使任务可以并发、限流、重试、断点续跑、计量和原子激活，并保证失败不会污染正式查询。

## 前置条件

- 阶段 02 的 extraction_runs、run_checkpoints 和 staging 结构可用。
- 阶段 03 能稳定产出章节和 raw chunk。
- 已有 fake generation/embedding provider。

## Run 生命周期

建议使用显式状态机：

~~~text
created
  -> running
  -> validating
  -> ready_to_activate
  -> active

running/validating
  -> failed
  -> retrying
~~~

状态转换必须在事务中完成。active 是查询可见性的唯一入口；不得通过修改多张表中的散落标志模拟激活。

## 实施顺序

### 1. 配置快照

每个 run 保存：

- book_id；
- 输入 content hash；
- pipeline、prompt、compression、schema version；
- generation/embedding profile ID 和 config hash；
- 创建时间、开始/结束时间和最终状态。

启动时计算完整运行指纹。配置缺失或 hash 不一致时禁止复用旧 checkpoint。

### 2. 章节 checkpoint

唯一键严格采用定版方案中的全部字段。每章 Map 结果写入 staging 后立即提交 checkpoint。

- 完全匹配才允许命中；
- 章节内容或任一版本改变即失效；
- checkpoint 复用需要记录来源 run；
- 复用不能绕过当前 run 的最终验证。

### 3. worker 与 writer

- 8–16 个抽取 worker 是生产目标，不是初始默认值。
- worker 只产出已通过 Schema 校验的 Draft 或结构化错误。
- 通过有界队列向单 writer 传递结果。
- writer 批量事务写 staging。
- 队列满时产生背压，不能无限占用内存。

先使用 1–2 个 worker 验证正确性，再通过压测确定并发。

### 4. 调用治理

- 全局令牌桶控制请求数、Token 和并发。
- 超时、可重试错误使用带抖动的指数退避。
- Schema 或输入无效属于不可重试错误。
- 设置单次调用和单章最大重试次数。
- 记录被丢弃响应，防止重试成本不可见。

### 5. Token 账本

每次调用记录：

- input tokens；
- cached input tokens；
- reasoning tokens；
- output tokens；
- retry 次数及消耗；
- discarded tokens；
- provider/model/profile；
- book/run/chapter/stage。

统计必须能汇总到章节、阶段、run 和整本书。

### 6. 验证与激活

激活前验证：

- 章节任务全部完成或有明确豁免；
- Schema 和外键完整；
- canonical 映射完成；
- evidence 验证完成；
- 索引版本完整；
- 数据量及错误比例在阈值内。

激活操作应瞬时且有界。失败时保持旧 run 可查。

### 7. 故障注入

使用 fake provider 和测试钩子模拟：

- 第 N 章超时；
- 无效 JSON；
- writer 事务失败；
- 进程在 checkpoint 前后退出；
- 激活前验证失败；
- 相同任务重复投递。

## 产物

- run state machine；
- checkpoint service；
- worker/queue/writer；
- retry 和 rate limiter；
- Token/cost ledger；
- validator 和 atomic activator；
- 故障恢复测试。

## 验证

- 中断重启后只重跑未成功章节。
- checkpoint 键任一字段变化都会失效。
- 重复任务不会产生重复正式数据。
- writer 失败不会留下部分事务。
- 新 run 失败时旧 active run 始终可查询。
- Token 汇总与模拟 provider 返回值一致。

## 退出标准

- 3–5 章 fixture 可在故障注入下最终收敛为单一 active run。
- 所有不可重试错误可定位到具体章节和阶段。
- 无部分激活、无静默跳章、无无限重试。
- 流水线框架不依赖具体模型厂商。
