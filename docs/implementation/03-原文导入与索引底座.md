# 03 原文导入与索引底座

## 目标

建立不依赖模型的原文权威底座：规范化文本、稳定章节、token chunk、全文检索和可替换向量索引。

## 前置条件

- 阶段 02 的 books、chapters、raw_chunks、embedding_records 等表可用。
- 已确定生产 tokenizer 接口。
- 准备包含中文标点、组合字符、空行和异常章节标题的 fixture。

## 实施顺序

### 1. 原始文件导入

- 首先支持 TXT，EPUB 作为后续适配器。
- 原始文件只读保存或记录可靠来源位置。
- 计算原始内容 hash。
- 导入过程必须绑定 book_id。

### 2. 文本规范化

固定执行：

- UTF-8 解码；
- Unicode NFC；
- 换行统一为 LF；
- 记录规范化前后 hash；
- offset 使用 Unicode code point；
- 区间统一为半开区间。

规范化函数必须纯粹且幂等。任何策略变化都要更新 normalization version。

### 3. 章节识别

- 规则识别章节标题并生成候选边界。
- 对无法确定的边界输出诊断信息，允许人工覆盖。
- chapter_id 导入后持久化，重排只更新 ordinal。
- 保存标题、全书 char range、content hash 和来源映射。
- 插章和内容修订需要有明确的匹配与失效规则。

### 4. raw chunk

- 使用 embedding tokenizer，而不是字符数切分。
- 默认目标长度和重叠比例来自版本化配置。
- 保存 token/char range、token count、content hash 和 profile。
- chunk_id 不依赖 ordinal。
- chunk 必须落在单一章节内。

### 5. FTS

- 选择并冻结中文切词方案。
- 索引规范化原文及必要的结构化摘要。
- 所有查询必须先限定 book_id。
- 建立专名、原句、标点差异和短查询测试集。

### 6. 向量索引接口

- embedding provider 与存储后端通过 profile 隔离。
- 运行时校验向量维数、归一化和距离度量。
- 不同维数使用独立虚表或索引。
- 元数据保留在普通表。
- 若后端不能在 Top-K 前过滤，按 book/profile 隔离索引。

阶段退出不要求连接真实远程 embedding；确定性 fake embedding 可先验证版本切换与过滤。

### 7. 修订与原子切换

章节 content hash 变化时：

1. 标记该章旧 chunk 和关联证据待失效；
2. 建立新版本 chunk 和向量；
3. 完整性验证；
4. 原子切换 active index version；
5. 旧版本保留审计或按维护策略清理。

查询期间不能看到新旧版本混合。

## 产物

- TXT importer；
- normalization 和 chapter splitter；
- tokenizer chunker；
- FTS 索引；
- embedding provider/storage 接口；
- 索引版本和切换机制；
- 原文/offset 黄金测试集。

## 验证

- 规范化重复执行结果完全一致。
- 每章 char range 可从全书规范化文本精确切回。
- raw chunk 覆盖章节且无非预期空洞。
- span hash 往返成功率 100%。
- FTS 可召回黄金集中的专名和原句。
- 多书查询不会返回其他 book_id。
- 修改一章只触发该章相关索引重建。

## 退出标准

- 任意直接证据都具备可靠的原文定位基础。
- 原文 FTS 已经可以独立提供可用检索。
- chunk/index 配置变化能够生成新版本并原子激活。
- 整个阶段在无生成模型条件下可重复运行。

## 暂不实现

- 原文压缩；
- claim 抽取；
- RRF 和答案生成；
- 面向全量小说的性能优化。
