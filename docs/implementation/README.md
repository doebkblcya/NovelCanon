# NovelCanon 实现文档

本目录把《定版方案》拆成可以逐步交付的工程流程。定版方案定义“系统必须满足什么”，这里描述“按什么顺序实现、如何验证完成”。

## 使用原则

1. 严格按编号推进；后一阶段可以提前做技术验证，但不能绕过前一阶段的退出标准。
2. 每个阶段都先补测试和黄金样例，再扩展实现。
3. 正式事实只能从通过验证并已激活的 run 查询，staging 数据不得混入默认查询。
4. 数据结构或语义与《定版方案》冲突时，以定版方案为准；若确需改变，先修改定版方案及版本号。
5. 真实模型、向量服务和大规模语料应晚于本地确定性链路接入。

## 首个里程碑

阶段 01–05 共同构成第一个里程碑：

> 导入一篇 3–5 章中文黄金样例，完成文本规范化、切章、FTS、固定 Draft 入库、证据 hash 验证、幂等激活，并支持带 knowledge_cutoff_chapter 的事实查询。

该里程碑不依赖真实生成模型、远程向量服务、复杂消歧或摘要。完成后才能证明数据模型、offset、run 生命周期、版本幂等和知识截止过滤的基础正确性。

## 阶段状态记录

建议在实施过程中维护以下状态，不在本文档中填写临时进度：

- issue/milestone：记录阶段任务和负责人；
- 测试配置：保存冻结的验收阈值；
- ADR：记录关键技术选择；
- extraction run：记录每次数据处理的配置和结果。
